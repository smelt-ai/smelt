# Product

## Platform

adaptive

视觉语言两端统一（同一套 Smelt 设计语言，iOS 与 Android 长得一样）；只有平台**行为**各随系统：返回手势（iOS 边缘右滑 / Android 预测性返回）、安全区与窗口 inset、系统字号缩放（Dynamic Type / sp）、触感反馈、系统分享与权限弹窗。不做两套控件。

## Users

在自己的 Mac 或 Linux 机器上同时跑多个编程 agent（Claude Code、Codex、Copilot、Grok、Pi 等）的开发者。用手机的场景是**人不在电脑前**：开会、通勤、下班后 agent 还在跑。他们要的是：知道哪台机器上哪个 agent 卡住了、一点允许 / 拒绝、必要时回一句短话，偶尔看一眼对话或终端。

一个人通常配对**多台**运行时（工作 Mac、家里 Mac、Linux 服务器上的无头 smeltd）。

## Product Purpose

Smelt 手机端是多台运行时的**指挥台**，不是第二块聊天客户端或小终端。成功标准：从掏出手机到处理完一条待批权限，几秒内完成；不用记得事情发生在哪台机器上。

## Positioning

引擎和会话留在用户自己的机器（`smeltd`）上，手机经 iroh 点对点直连，不经过任何云端网关；一台手机同时挂上所有配对过的机器，跨机器汇总「等我处理 / 正在跑 / 刚完成」。权限门永远不关。

## Operating Context

- 单手、碎片时间、可能在弱网或刚从后台切回来；连接可能正在重连。
- 离线时先读本地 SQLite 缓存（会话列表、最近几段对话尾部），再在连上后刷新。
- 配对：扫桌面或 `smeltd pair` 给出的一次性二维码（10 分钟、只能用一次）；设备可被运行时撤销。
- 平板（iPad / Android 平板）上是列表 + 详情双栏。

## Capabilities and Constraints

- 每台运行时提供：会话目录（结构化对话 ACP / 终端 PTY 两类，带相位：运行中、等审批、等输入、完成、失败、空闲）、attention 提醒、工作区项目与可启动的 agent、智能体定义、自动化（开关、立即运行、最近运行）、历史会话（恢复、改名）。
- 对话：markdown 正文、工具调用卡（含 diff / 终端输出）、计划、后台任务 / 子智能体便签、图片（缩略图按需取原图）、审批（允许一次 / 总是允许 / 拒绝）、选择题与表单（elicitation）、模型 / provider / 配置项切换、斜杠命令与技能、上下文用量、取消回合。
- 终端：运行时转发的 PTY 字节流，xterm 渲染，快捷键栏、复制粘贴、点链接。
- 逻辑全在 Rust 内核 `crates/smelt-mobile`（经 flutter_rust_bridge），Flutter 只做界面；界面不解析协议。
- 界面文字中英双语，跟随系统语言。
- 不做：手机端 H5 / PWA；在手机上跑 agent；推送通知与深链目前未实现（是规划中的能力，不要在界面上假装已有）。

## Brand Commitments

- 产品名 **Smelt**（小写 `smelt` 用于命令与仓库名）。App 图标 `assets/icon-1024.png`（仓库根目录）。
- 各家 agent 的身份图标沿用桌面端那套（LobeHub Icons，MIT），放在 `mobile/assets/agent-icons/`。
- 移动端有项目色块（`projectAccent`），桌面端只用状态点。

## Evidence on Hand

- 真实数据来自运行时：会话标题、项目路径、agent 名、工具调用、diff。界面演示可以用合成数据，但要标明。
- 没有用户评价、客户名单、性能基准，不得编造。

## Product Principles

1. **先回答「有事等我吗」**：首屏是跨机器的待办，不是项目树或聊天列表。
2. **机器是上下文，不是门槛**：不要求先选机器再看内容；机器身份随每一条内容走，必要时可按机器筛选。
3. **一次触达**：批权限、回一句话不离开当前上下文能完成。
4. **诚实的状态**：连接中、离线缓存、重连、被撤销都要说清楚，旧数据不能冒充新数据。
5. **权限门不关**：任何「全部允许」都必须是显式、可见、单条确认的。

## Accessibility & Inclusion

- 触控区 iOS ≥ 44pt、Android ≥ 48dp；跟随系统字号（含大号字）；深浅色都是一等公民；尊重「减少动态效果」；状态不能只靠颜色表达。
