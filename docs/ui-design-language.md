# smelt 视觉设计语言 · Discord 基调 + TG 液态玻璃 + Codex 结构

三个参照对象不是三选一，而是三个不同维度，各管一件事：

| 维度 | 参照 | 管什么 | 现状 |
|------|------|--------|------|
| **色彩与情绪基调** | Discord | 全局配色、强调色、状态识别方式 | 已落地：`ui_theme.rs` 色板本身就是 Discord 取色 |
| **材质/质感** | Telegram 液态玻璃 | 卡片/面板的「毛玻璃」质感 | 已落地一半：仅整窗 vibrancy，未下沉到卡片级 |
| **信息组织结构** | Codex（Copilot CLI 桌面版） | 一块区域内怎么分组、怎么排 | 未落地：侧栏/通知目前是扁平列表 |

结论：**不用重新选风格，现有底子是对的，缺的是把「材质」和「结构」两件事从
「整窗一份」下沉到「每张卡片/每个信息面板各自一份」。**

---

## 1 · Discord 基调（色彩与身份识别）——已落地，需要延伸

`ui_theme.rs` 的色板已经是 Discord 语言：`bg_rail`（最深）/`bg_elev`/`bg_panel`
三级表面 + blurple 强调色 + 语义化状态色。这部分**不用重做**，只需要把它现有的
「表面层级」思路，延伸到 Discord 真正出彩的地方——**身份识别**：

- 项目 rail（`session_list.rs` 左列）目前是纯文字/图标列表，Discord 服务器栏是
  「彩色图标 + 右上角状态点」。smelt 的等价物应该是：**每个项目一个色块/图标 +
  agent 运行状态点**（运行中 = 呼吸动画的 accent 色点，等待批准 = 黄点，出错 =
  红点，空闲 = 灰点，无点缀）。这是「不用点开就知道哪个项目需要你」的核心体验，
  目前完全没做。
- 未读数字徽标（Discord 红色圆点+数字）——smelt 的通知计数（`notif_count`，见
  main.rs）已经有数字，但只在标题栏铃铛上，没有下沉到项目 rail 的每个图标角标。

## 2 · TG 液态玻璃（材质）——已落地在窗口级，需要下沉到卡片级

`Appearance.blur` → `ui_theme::set_liquid_glass()` 这条链路已经做了「整窗毛玻璃」：
`shell_surface`/`sidebar_surface`/`stage_surface` 三层用 `tint()` 调半透明度，
配合系统合成器的 vibrancy，做出「深色沟槽 + 半透明面板」的效果（见
main.rs:5170-5214 的注释，这正是你之前那次「最外层背景」调整）。

差距在于：**这套质感现在只在"三大栏"这个粗粒度上生效，卡片级的小面板
（通知条目、git 变更文件行、任务卡）还是走 `bg_card` 实色**，跟 TG 频道里"每条
消息都是独立的一小块磨砂玻璃"不是一回事。要补的：

- 把 `bg_card` 在 `is_liquid_glass()` 开启时也过一遍 `tint()`，做出「卡片自己
  半透明 + 描边发光」而不是「卡片实色贴在半透明面板上」。
- 卡片圆角、内边距、投影目前分散在各处硬编码，应该在 `ui_theme.rs` 里补一组
  `card_radius()` / `card_padding()` token，跟色板一样统一出处。
- TG 的卡片是"可独立悬浮的最小单元"（置顶消息、状态标签都是卡片内再嵌小卡片）。
  smelt 里对应的是 `git_panel.rs` 的变更文件行、`session_list.rs` 的通知条——这些
  应该长成"卡片里套卡片"的样子，而不是扁平的行。

## 3 · Codex 结构（信息组织）——未落地，是这次讨论的主要缺口

Codex 桌面版右侧「环境 / 附带任务 / 来源」三段式分组是关键：**同一个面板里，
不同性质的信息要分组、每组有标题、每组内部才是列表**。smelt 现状是很多面板
（`git_panel.rs`、`inspector.rs`）把变更文件、分支信息、来源混在一个扁平列表里。

要补的信息架构（对应到现有文件）：

- `git_panel.rs` / `inspector.rs`：拆成「环境（分支/远端/工作区路径）」「变更
  （文件列表 + diff 统计）」「操作（提交/推送/比较分支）」三组，组间用 8px 间隙
  + 弱分隔线（复用 `border_dim`），不需要边框盒子。
- 通知/事件（响铃、OSC 通知）目前没有独立的"信息流面板"，只有铃铛+计数。可以
  参考 TG 频道 + Codex「附带任务」的结合体：**一条事件 = 一张小卡片**（来源
  项目图标 + 一句话 + 时间 + 点击跳转对应终端标签），按项目分组或按时间倒序，
  而不是纯数字提醒。

---

## 落地顺序建议

1. `ui_theme.rs` 补卡片级 token（`card_radius`/`card_padding`，`bg_card` 在
   liquid glass 下的半透明变体）——工作量小，其它两项都依赖它。
2. 项目 rail 加状态点 + 未读角标（Discord 身份识别）——独立可做，视觉冲击最大。
3. 新增「事件卡片流」面板（TG 卡片 + Codex 分组），替代/增强现有铃铛计数。
4. `git_panel.rs`/`inspector.rs` 按 Codex 三段式重排分组。

不建议一次性重做——三项分别是独立可验证的小改动，做完一项就能看到效果，
避免大改动导致 `cargo check` 长时间不过。
