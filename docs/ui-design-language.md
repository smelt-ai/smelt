# smelt 视觉设计语言 · 整体参考 Grok Bot

唯一视觉参照：本机 **Grok Bot.app** 的 `sand` 设计系统（色板已从该应用抽出，落在 `ui_theme.rs`）。

不再参照 Telegram 液态玻璃，也不再把 Codex / Discord 当成视觉来源。多会话、审批、git、终端、手机指挥台是 **产品结构**，不是另一套皮肤——这些面仍然用 Grok Bot 的侧栏 / 对话 / 信息面板语法去画。

| 层 | 跟 Grok Bot 什么 | 不跟什么 |
|---|---|---|
| 色彩 | sand 表面梯子、强调蓝、近白/近黑主按钮 | Discord blurple、舞台最亮的旧层级 |
| 材质 | 实色近黑、卡片是抬起的实底、描边是半透明 overlay | Telegram 嵌套磨砂卡、整窗内容区毛玻璃 |
| 对话壳 | 768 居中阅读栏、胶囊 composer、白圆发送、空状态大标题 | 功能卡片墙、强调蓝实心 CTA |
| Chrome | 栏贴窗口边、矩形分栏、栏间发丝 | 壳里三张圆角浮卡、10px 窗口内边距 |
| 身份 | 侧栏状态点（非空闲才画） | 不要为未使用的项目色块预留桌面 API |

macOS 26 顶部导航的 `NSGlassEffectView` 是 **系统窗口铬**，不是视觉语言。内容区按 Grok Bot 画实底；不要借这层系统玻璃去给卡片做磨砂。

---

## 1 · 色彩（已落地）

`ui_theme.rs` 的 `DARK` / `LIGHT` 取自 Grok Bot sand：

- 深色：窗口底和舞台底同色近黑 `#070707`，会话列表 / 卡片往上抬 `#111111` / `#181818`
- 浅色：舞台底近白 `#fcfcfc`，列表和卡片略压暗
- 强调蓝 `#1084fe` 只给焦点、链接、选中描边
- 主操作走近白 / 近黑实心（`action_fill` / `action_on`），不走强调蓝
- 深色 **舞台最暗**。Discord 那套「舞台最亮、边缘压暗」不要改回去

桌面侧栏身份目前就是状态点：运行中蓝、要你红、空闲不画。项目色块只在移动端画（`projectAccent`），桌面不预留未接的 `project_color`。

---

## 2 · 材质（从 TG 毛玻璃改回 Grok Bot 实色）

Grok Bot 的表面是 **不透明的 sand 实底**。卡片比舞台抬一档，靠色阶而不是模糊。描边是 `overlay` 半透明，阴影只给真正的浮层（菜单、弹窗、composer），不给整栏外壳。

对应 token：

- 栏和内容卡：`bg_column` / `bg_card` / `bg_stage` 实色
- 浮层：实色 `bg_card` + `shadow_lg`（补全、对话框）
- composer：实色抬起 + `composer_radius` 胶囊，不是 12px 玻璃卡
- `glass_*` 名字是历史残留，实现必须是实色。不要再往卡片上叠半透明去「做出毛玻璃」

圆角层级跟 Grok Bot 一致：行 8px、内容卡 12px、composer 24px 胶囊。**窗口分栏本身不圆角**——圆角是控件和卡片的事，不是三栏外壳的事。

---

## 3 · Chrome（贴边，不浮卡）

Grok Bot 是整窗一块近黑：侧栏贴左边、对话贴中间、信息面板贴右边，栏间一条发丝。不是「透明壳里托三张圆角卡」。

要画成：

```
┌────────────┬──────────────────────┬─────────────┐
│ 会话列表    │ 舞台（对话 / 终端）    │ 文件 / 变更  │
│ bg_column  │ bg_stage             │ bg_column   │
│            ├──────────────────────┴─────────────┤
│            │ 底栏终端（可选）                      │
└────────────┴────────────────────────────────────┘
```

- 窗口内边距 `shell_padding` = 0，栏贴边
- 分栏矩形、裁切溢出、不投影
- 栏间保留 6px 输入安全槽。1px 发丝仍画在 gpui 分栏手柄上（`resizable.handle` = 半透明 overlay）；安全槽用于避免原生 WebView 子窗口截走分栏拖拽起点
- 舞台头尽量薄。访达 / IDE 入口不要长成工具条

底栏终端、右栏文件 / git 是 smelt 的产品面，位置可以留，**画法**仍是 Grok Bot 信息面板：实底、发丝、分组标题 + 列表，不是嵌套玻璃卡。

---

## 4 · 对话壳（ACP 已在这条路上）

会话页按 Grok Bot 对话来：

- 阅读栏最大 768px，居中
- 用户气泡右对齐；助手正文左对齐 markdown，不套大气泡
- 底部胶囊 composer：输入 + 发送圆钮。模型 / 上下文收到 composer 里，不在标题栏再做一套主按钮
- 发送钮近白 / 近黑；停止才用红
- 空状态：agent 名 + 一句「想让它做什么？」+ 安静的圆芯片。不要功能卡片墙

工具调用、PLAN、审批是 agent 工作台多出来的信息，用 Grok Bot 的小卡片 / 折叠组收进去，不要把对话页画成 IDE 日志。

---

## 5 · 产品结构仍是指挥台

视觉跟 Grok Bot，并不把 smelt 收成「一个空画布 + 输入框」：

- 桌面默认仍是多会话工作区，不是单 thread
- 手机默认仍是指挥台（等我处理 / 正在跑 / 刚完成），不是第二块聊天客户端
- 权限门、git、终端继续存在，只是换 Grok Bot 的表面和控件语言

「最好的 UI 是没有 UI」只作用于 **对话页的铬**，不能砍到待办和审批看不见。

---

## 落地顺序

1. **材质 + 外壳去 TG**（本轮）：内容区实色、分栏去掉圆角投影、窗口贴边。系统顶栏玻璃保留。
2. **栏间发丝**（本轮）：`chrome_gap` = 6px，发丝由分栏手柄绘制；这 6px 同时是原生 WebView 与 GPUI 拖拽层之间的输入安全槽。
3. **项目身份**：桌面侧栏保持状态点；项目色块只在移动端。
4. **对话壳收束**：composer 信息密度、空状态、工具卡继续按第 4 节收。

一次只做一层，做完就能看出是不是更像 Grok Bot。不要再往卡片上加透明度或嵌套磨砂。
