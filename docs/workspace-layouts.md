# 可定制、可切换的工作台布局

状态：设计稿，未开工。对应 #260，总任务 #257；分享导入是 #259，事件订阅是 #261，看板是 #258。

## 要解决的问题

工作台外层是 `workspace_shell.rs` 里的一个 `DockArea`：左栏、舞台、工具面板三块，位置写死、Dock 锁住、布局树不存。插件只能挂成工具面板的一个 tab。用户想把会话做成看板、把工具面板挪到别处、换一套整窗排布，都得改 Rust。

验收（照 #260）：

- 不改 Rust 源码就能新建一套布局并切换过去。
- 重启后恢复上次的有效布局；无效布局不会让工作台不可用，默认布局随时能回去。
- 布局切换、恢复、组件不可用、加载失败都有用例。

## 参照：herdr

[herdr](https://github.com/herdrdev/herdr-app) 是同一套技术栈（gpui-kit 的 gpui-shell 写 JS 界面）的终端工作台，已经把这件事做完了，还有社区画廊（herdr.dev/gallery，几百个布局和 mod，其中 Kaiju City 就是按状态分列的智能体看板）。它的做法：

- **布局是文件。** `layouts/<名字>.json` 一份一扇窗，树形，节点只有 `row` / `column` / `stack` / `block` 四种，`block` 放 mod、终端或当前标签页。人和智能体直接改文件，存盘即生效。
- **点出来的状态另存。** 拖的宽度、显隐、stack 选中哪块存在 `layouts/.state/`，和布局文件分开；文件改过的字段以文件为准。
- **窗口外框归布局根。** `titlebar: "none"`、`traffic_lights: [x, y]`、节点上的 `window_drag`，不让某块面板默认自己在左上角。
- **出错兜底。** 文件坏了继续用上一份能用的，原因写进 `<名字>.error`；有一个不能改绑的快捷键回默认布局。自带布局只读，要改先「复制」。
- **组件很细。** 侧栏、标签栏、状态栏、文件、变更全是 mod，原生的只有终端和窗格。
- **给智能体的配套。** 每次启动重写一份使用说明和类型文件；`check` 命令加载一次报错；`shot` 截窗口。

我们拿来的：布局是声明文件、定义和点出来的状态分开、窗口外框不绑在某块面板上、坏了用上一份、自带只读要复制、给智能体的校验命令。

不照搬的：

- **不自写布局引擎。** 外层继续用组件库的 `DockArea`，把声明树映射成 `DockLayout`，和 `term_dock` 一样（见「怎么搭」）。
- **组件不拆那么细。** 第一阶段内置组件就是现在的三大块，侧栏等有具体场景再拆。
- **布局里不放外观。** herdr 的布局带主题、字体、背景；我们的外观仍归设置的外观页，布局只管排布。
- **插件刷新不靠定时器。** herdr 的 Files 面板 10 秒刷一次；我们按 #261 做事件订阅。

## 决定

1. **布局定义是文件，和插件一样当作配置或代码**，放 `~/.smelt/layouts/<id>.json`，带格式版本。它是人和智能体编写、会随插件一起分享的东西，不是业务数据。
2. **点出来的状态和当前用哪套布局进 SQLite。** 宽度、开合、标签组选中哪个，按 AGENTS.md 的例外存成一个带版本的 JSON 字段：整块读写、从不按局部查。
3. **布局只引用组件。** 组件是内置区域或插件，按名字注册。布局文件里只出现组件名，不出现 Rust 类型。
4. **外层仍是一个 `DockArea`。** 声明树翻成 `DockLayout` 装进去；Dock 继续锁住，这一阶段不做拖动编辑。
5. **窗口外框归宿主。** 红黄绿按钮的避让、拖动窗口的顶条，按「哪块面板贴着窗口左上角、哪些贴着顶边」来算，不再写在侧栏和舞台里。
6. **默认布局写在代码里**，不是文件，坏不了、删不掉；恢复默认的入口不依赖当前布局里有什么。
7. **会话内终端分屏不动。** 它仍是舞台里另一个 Dock（`term_dock`），存档、恢复照旧。

不在这次范围：

- 拖动编辑布局：Dock 解锁后拖标签、另存。
- 浮在布局上的块、插件注册命令和快捷键、工作台级弹层（#257 第 5 项）。
- 布局里的外观。
- 分享导入（#259）：格式为它留好，见「分享」。
- 侧栏拆成更细的组件。
- 同一个插件在布局里出现多份、按参数画不同角色（herdr 的 `props`）。

## 组件

组件名就是布局文件里写的字符串。

| 组件名 | 是什么 | 现在由谁画 |
|---|---|---|
| `smelt.sessions` | 会话列表（侧栏） | `render_sidebar_dock` |
| `smelt.stage` | 舞台：会话、智能体页、自动化、能力、远程桌面，以及放大到舞台的工具面板 | `render_stage_dock` |
| `smelt.tools` | 工具面板：Files / Git / History，加上没放进布局的插件 tab | `render_tool_dock` |
| `plugin:<插件 id>` | 一个插件，id 是 `gpui-shell.json` 里的 `id`，如 `plugin:com.smelt.skills` | 插件自己的 `ScriptView` |

- 内置组件在 Rust 里登记一张表（名字 → 建面板的函数），替代现在 `register_shell_panels` 里写死的三个。以后拆侧栏，就是往表里加名字，布局格式不变。
- 每个插件自动就是一个组件，manifest 不用加字段。
- **一个组件在一套布局里最多出现一次。** 插件视图一个插件只挂一份（`plugins::Registry.panels`）；同一个实体画在两处，焦点、滚动、任务都会乱。
- **放进布局的插件不再出现在工具面板的 tab 里**；工具面板只列没被布局摆出来的插件。会话存档里「当前 tab 是某插件」遇到这种插件时显示成 Files，但不改存档：切回不摆这个插件的布局，tab 就回来了。

## 布局文件

### 放哪、谁赢

和插件同一套来源与顺序（`plugins::plugin_dirs`）：

1. `~/.smelt/layouts/`：用户的。
2. App 自带的 `Contents/Resources/layouts/`：只读。
3. debug 构建读仓库里的 `layouts/`。

同 id 时前面的赢，和插件一致。id 就是文件名去掉 `.json`。`default` 留给代码里的默认布局，文件用这个名字会报错、不加载。

### 格式 v1

```json
{
  "format": 1,
  "name": "看板",
  "description": "左边会话列表，中间看板和舞台左右分，右边工具面板",
  "copied_from": "default",
  "left":   { "size": 260, "tabs": ["smelt.sessions"] },
  "center": {
    "split": "row",
    "children": [
      { "size": 420, "tabs": ["plugin:com.smelt.kanban"] },
      { "tabs": ["smelt.stage"] }
    ]
  },
  "right":  { "size": 360, "open": false, "tabs": ["smelt.tools"] }
}
```

- `format`：格式版本，现在只有 `1`。不认识的版本整份不加载，报「这个布局比当前 smelt 新」。
- `name` / `description`：设置页和命令面板里显示；`copied_from` 记从哪套复制来的，只用来显示。
- `left` / `right` / `bottom`：停靠区，都可以省。每个停靠区是一棵树，外加 `size`（像素）和 `open`（默认开）。
- `center`：必填，一棵树。
- 树的节点只有两种，和 `DockLayout` 一一对应：
  - `{ "split": "row" | "column", "children": [...] }`：横排或竖排；每个子节点可带 `size`（像素），不带就均分剩下的。
  - `{ "tabs": [组件名, ...], "active": 0 }`：标签组；只有一个组件时不显示标签条（现在就是这样）。

没有 herdr 的固定高度条、`floating`、`window_drag` 和外观字段。Dock 的分隔条都能拖；能不能有「不能拖的固定条」看组件库支不支持，不支持就不加。

### 校验

解析和校验是纯数据，不碰窗口，放进 `smelt-client`（`smelt` 和 `smelt-cli` 都依赖它），桌面和命令行用同一份。

整份不加载、报错，继续用当前布局：

- JSON 坏了、`format` 不认识、字段类型不对。
- 没有 `smelt.stage`，或者它出现了不止一次：会话和各个页面都画在舞台里，没有它就没地方显示。
- 同一个组件出现不止一次。
- 不认识的 `smelt.*` 组件名：写错了，或者是给更新版本写的。
- 空的 `split` / `tabs`，`active` 越界。

照常加载，在原位放一块错误面板：

- `plugin:<id>` 指的插件没装，或者加载失败。面板里写原因，提示去设置的插件页。和现在插件加载失败也占一个 tab、把错误画出来是同一个思路。

可以没有 `smelt.sessions` 或 `smelt.tools`（比如只要看板和舞台的布局）。这时「切换侧栏」「切换工具面板」两个命令不可用，命令面板和快捷键提示里灰掉。

## 点出来的状态

现在的权威数据和改成布局后归谁：

| 状态 | 现在存在 | 改后 |
|---|---|---|
| 会话列表所在停靠区的开合、宽度 | `workspace_ui.sidebar_open` / `sidebar_w` | 不变。哪个停靠区放着 `smelt.sessions` 就用它，不管是左还是右 |
| 工具面板所在停靠区的开合、宽度 | 每段对话的 `tool_panel_open` / `tool_panel_w` | 不变。仍跟着会话走，渲染前由 `align_shell_dock` 写进 Dock |
| 其余停靠区的开合和大小、拆分比例、标签组选中哪个 | 没有（布局固定） | 新表 `workspace_layout_state` |
| 当前用哪套布局 | 没有 | `workspace_ui` 加一列 `layout_id` |

每份状态只存一处：放会话列表和工具面板的停靠区，宽度和开合不进新表，免得两份对不上。

```sql
CREATE TABLE workspace_layout_state (
  layout_id TEXT PRIMARY KEY,
  -- 读到这份状态时布局文件的指纹（内容哈希）。文件改过就整份丢掉，回到文件里写的初值。
  file_digest TEXT NOT NULL,
  -- 自定义格式 {"v":1, "nodes": {...}}；版本不认识或内容不合法时当作没有。
  state TEXT NOT NULL CHECK (json_valid(state))
);
```

- 节点按树里的路径认（如 `center/1`），不用 Dock 的 `NodeId`：`NodeId` 每次启动重新分配。
- herdr 是逐个字段比「文件改过没有」。我们先整份比：改了布局文件就丢掉点出来的状态，简单、不会半新半旧。
- `default` 布局也有一行状态。

## 怎么搭

### 启动

1. `plugins::mount_all`（已有，先于读存档）。
2. 读布局文件，校验 `workspace_ui.layout_id` 指的那套。读文件在启动事件里做，不在 render 里。
3. 找不到或不合法就用 `default`，进工作台后提示一句原因。不改存档里的 `layout_id`：可能只是插件或文件暂时不在，下次启动它好了就还用它。
4. 按声明树和点出来的状态拼 `DockLayout`，`set_center` / `set_dock` 装进外层 `DockArea`，然后 `set_locked(true)`。

### 切换

入口三处：设置里新的「布局」页（列出所有布局，标明来源和错误），命令面板，`切换布局` 快捷键（默认不绑）。

1. 先完整解析、校验新布局，失败就不动 Dock，弹提示。
2. 内置组件的面板实体按组件名缓存，切换时复用：会话列表的滚动位置、舞台里的终端不会因为切布局而重建。插件视图也复用同一个实体，不重新跑脚本。
3. 用新树重装 `DockArea` 的各个区域，没有的停靠区 `remove_dock`。
4. 写 `workspace_ui.layout_id`。

### 文件变化

- 用 `notify` 监听布局目录（主程序里已经在用这个库监听自带守护进程的二进制）。收到变化后合并同一批事件，再重读变了的文件。
- 当前布局的文件改了且仍合法：重新装，状态按指纹丢掉。改坏了：继续用上一份能用的，设置的布局页和提示里显示原因。
- 插件重新加载（`mount_all`）后插件视图换了新实体，当前布局跟着重装一次。

### 恢复默认

- 「恢复默认布局」放在 macOS 应用菜单和命令面板里，再加一个固定快捷键。这几处都不依赖当前布局里有什么。
- 「复制布局」：把选中的布局（`default` 也行）写成 `~/.smelt/layouts/<id>-copy.json`，带上 `copied_from`。名字已被占用就加编号。复制完切换过去。
- 自带布局在只读目录里，改不了；要改就先复制。

## 窗口外框

现在：侧栏顶部留 80px 给红黄绿按钮，再铺一条拖动窗口的顶条（`render_sidebar_dock`）；侧栏收起时舞台左边让出 48 或 128px（`chrome_left_guard`）。都默认侧栏在左、舞台在中。

改成宿主按位置算：

- 每块面板外面包一层宿主的壳，记下上一帧的位置（在 prepaint 里记，变了才通知，render 只读这份）。
- **贴着窗口左上角的那块** 让出红黄绿按钮的位置。侧栏收起时舞台贴到左上角，就由它来让，和现在的 `chrome_left_guard` 等价，只是不再按「侧栏开没开」判断。
- **贴着窗口顶边的面板**：内置组件本来就有自己的顶栏，照旧当拖动区。插件面板由宿主在上面画一条细标题栏（插件名，能拖窗口），插件自己不用管窗口外框。
- 默认布局的效果和现在一样，这条要有用例盯住。

## 给智能体的配套

- **`smelt layout check <文件>`**：用 `smelt-client` 里同一份校验，不用开桌面；插件在不在按插件目录查。有错时非零退出，并把错误原因打印出来。
- **`smelt layout list` / `smelt layout use <id>`**：要给桌面发指令。先看 #266 的命令是怎么到桌面的，有现成通道就加，没有就放到以后。
- **格式说明**：smelt 技能里加一节布局，启动时把 JSON Schema 写进 `~/.smelt/layouts/`。和插件目录写 `gpui-kit.d.ts` 一样：编辑器有补全，智能体照着写，版本始终和程序一致。

## 分享（留给 #259）

- 一套布局用到哪些插件，从文件里的 `plugin:<id>` 直接读出来，不另写依赖清单。
- 分享包可以照 herdr：一个目录，里面 `layouts/<id>.json` 加 `plugins/<id>/`，外加说明和预览图。导入时 id 撞了就改名，不覆盖。
- 安装前展示风险（#257 的要求）：herdr 交给智能体口头说明；我们由宿主列出要装的插件和它们声明的网络主机，并写明「插件可读写文件、执行命令」。

## 分阶段

1. **默认布局走新路径，界面不变。** 加组件注册表和布局模型，默认布局用它来搭；窗口外框改成按位置算；建状态表。这一步之后界面和现在完全一样。
2. **用户布局。** 布局目录、切换、坏了用上一份、恢复默认、复制、文件监听，加设置里的布局页。到这里 #260 的验收就满足了。
3. **智能体配套和示例。** `smelt layout check`、JSON Schema、技能里的说明。等 #258 的看板插件做完，再自带一套「看板」布局当样例。

## 测试

- 模型（纯数据，`smelt-client`）：
  - 各种不合法输入：坏 JSON、未知版本、缺舞台、重复组件、未知内置名、空节点、`active` 越界。
  - 插件缺失时照常加载、给出占位。
  - 状态的版本不认识或文件指纹变了时，回到初值。
- 搭建（照 `main_tests/term_dock_tests.rs`）：
  - 默认布局搭出来和现在的三块等价。
  - 切换时内置面板和插件视图是同一个实体。
  - 切到坏布局时 Dock 不变。
  - 少了会话列表或工具面板时，对应命令不可用。
- 窗口外框：
  - 默认布局下各面板让出的位置和现在一样。
  - 侧栏收起后，舞台接手红黄绿按钮的避让。
  - 会话列表放在右边时，左上角的面板来避让。
- 存储：建表和迁移的用例放 `smelt-client-store/src/tests.rs`；`layout_id` 指向不存在的布局时回到默认，并且不改写存档。
