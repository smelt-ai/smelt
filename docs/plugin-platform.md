# 插件平台：整个工作台可定制、可分享

状态：架构草稿。第 2 步已开工：`smelt-workspace` 有了 `changed()` 订阅、更全的会话字段、机器和项目，以及关会话、切项目；能列新建选项、起会话；会话看板（`kanban`）和左栏样例「队伍」（`party`）只用这些接口，放在示例仓库 smelt-ai/smelt-plugin-demo，不随 App 分发。第 3 步改成「组件统一」：先前把工具面板页签拆出来单独摆，是在三套放置系统之间打补丁，停下改底层，设计见「组件注册」和 `docs/workspace-layouts.md`。第 3 步做完又发现外层的 `DockArea` 把结构写死成几个区域：顶栏、状态栏、舞台顶条每样都要宿主加特例，布局先推倒成自己的通用树（v2），又发现那是在重写 Dock，最后直接用 gpui-base Dock 的官方格式 `DockAreaState`（v3，第 5 步），操作统一成命令（第 6 步）。总任务 #257；布局 #260（`docs/workspace-layouts.md`，`feat/workspace-layouts` 上有粗版本），看板 #258，分享导入 #259，事件订阅 #261。

## 目标

开放生态：第三方不改 Rust、不重新编译 smelt，就能

1. **加功能**：新面板、新命令、新的智能体技能。
2. **换掉任意一块界面**：会话列表、标签栏、状态栏都能换成自己画的。
3. **换外观**：配色、圆角，各区域自己的背景图。
4. **打包分享**：上面这些合成一个包，别人一次装好、随时切回默认。

参照物是 herdr 画廊里的 Traveler：左栏像素风项目卡和智能体卡（模型、状态、HP/SP），标签带头像，侧栏和舞台各一张背景图。这一整套在 herdr 里是布局 + 若干 mod + 外观，装一个包就有。

## 现状

扩展点各管一摊，没有统一的包和接口：

| 层 | 现在能扩展什么 | 缺什么 |
|---|---|---|
| 界面插件（gpui-shell，JS + QuickJS，GPUI 原生绘制） | 布局里任意位置的面板，没摆的从命令面板「添加面板」加；能画图片 | 宿主接口有 `smelt-fs`、`smelt-workspace`：当前项目、会话快照（类型、智能体、三态、未读、目录、所属项目、机器、模型、上下文用量、时间）、机器和项目、`changed()` 订阅、打开和关闭会话、切项目、新建会话、选目录、执行命令；一个插件可以声明多个面板和命令，命令进命令面板、可带默认快捷键；放置只有布局一套 |
| 布局 | 本分支 v3：官方 `DockAreaState` 格式的声明文件（任意拆分和标签组）、切换、恢复默认、存档就是 `dump()` | 文件改了不自动重载；没有 `smelt layout check`；插件的布局还没有名字 |
| 外观 | 设置页：22 套内置主题、整窗背景色/图、透明度、字体 | 主题编进程序；背景图只有一张整窗的 |
| 智能体（Pi） | 内置技能、MCP、Pi 扩展（如压缩调优插件） | 和界面插件是两套安装方式 |
| 守护 / CLI | Control API v3、`smelt` 命令、事件总线、自动化 | 界面插件用不上事件总线 |

## 分层

```
┌ 包（分享单位）─ 清单 + 贡献 + 资源 ───────────────────────────┐
│  布局     外观（主题 + 背景图等资源）   组件（脚本）   命令   技能 │
└──────────────┬──────────────────────────┬─────────────────────┘
               │ 引用组件名                │ 调宿主接口
┌ 组件注册 ─────┴─────┐      ┌ 宿主接口（带版本）─────────────────┐
│ smelt.* 内置（Rust） │      │ 快照 + 订阅 + 操作                 │
│ shell:<包>/<组件>    │      │ 内置界面用到的数据，插件都拿得到     │
└─────────────────────┘      └──────────────┬────────────────────┘
                                            │
                              工作台模型（客户端库 + smeltd 推送）
```

自下而上：

### 1. 工作台模型和宿主接口：接口对等

**原则：内置界面画得出来的，插件都拿得到。** 内置组件和插件读同一份模型，只是一个用 Rust 画、一个用 JS 画。做不到对等，插件就只能「在旁边加」，永远替不掉内置组件；生态卡在这里，不在布局。

- **快照 + 订阅 + 操作**三件套。订阅按主题分（项目、会话、机器、通知……），推送的是「变了」加新版本号，插件再读快照（#261）。空闲时没有唤醒。
- 模型字段按真实组件需要来补，不一次铺满。Traveler 那一栏要：会话的智能体、模型和推理强度、细分状态、上下文用量、额度；项目列表和每个项目的 git 摘要（未提交、未推送）；机器列表和在线状态；新建会话、关会话、切项目。
- 接口带版本：`smelt-workspace` 这类模块有主版本号，插件在清单里写需要的版本，不满足就不加载并说清楚原因。加字段不升版本，改语义、删字段才升，能不升就不升。
- 每个版本自动生成类型文件（gpui-shell 已经会往插件目录写 `gpui-kit.d.ts`，宿主模块的类型跟着写），智能体照类型改插件。

**命令**

「操作」不再一个个挑着开放成专用函数。界面上能点的每件事都是一条带参数的命令，内置按钮、快捷键、命令面板、插件（以后还有命令行）执行的是同一条：

- 插件用 `run(name, args?)` 执行，`commands()` 列出全部命令：名字、标题、分组、参数（名字、是否必填、说明）、眼下绑的键。缺一个操作就补一条命令，不补专用函数。
- 名字按对象分：`layout.select {panel}`、`project.select {machine, root}`、`project.new`、`machine.add`、`session.new {machine, root, key}`、`session.open {id}`、`session.close {id}`、`settings.open {page?}`……第 6 步定全表。现在能改键的那些（`split_beside`……）一并改名进来。
- 现在的专用函数 `select_project`、`new_session`、`open_session`、`close_session`、`open_settings` 换成命令后删掉，示例仓库和 Traveler 一起改，不留两套。读数据的（`sessions()`、`machines()`、`context()`、`new_session_options()`）和订阅 `changed()` 不变。
- 快捷键可以绑带参数的命令；没给参数、命令又要参数时按当前焦点和选中补（和现在按焦点派发一样）。
- 插件自己的命令（`<插件 id>/<命令名>`）仍按「插件的命令」声明，在同一张表里。

### 2. 组件注册

布局里引用的每个面板名都是一个组件。**放到界面上只有一条路：布局（Dock 的树）。** 没有第二套「工具面板页签」「插件槽位」。

**名字**

- **内置**：`smelt.sessions`、`smelt.stage`、`smelt.files`、`smelt.git`、`smelt.history`。集合是封闭的，Rust 里是一个枚举；内置组件**不改写成 JS**，终端、对话流这类重件留在 Rust，性能和输入法细节都在那里。
- **插件面板**：`shell:<插件 id>/<面板>`，插件往布局里放东西只有这一种。插件先在 `smelt.json` 里声明面板（见下面「插件的面板清单」），再在 `init()` 里调 gpui-shell 的 `DockArea.register_panel("board", Board)`，注册进 gpui-kit 的全局面板注册表，名字就是布局里写的 `shell:<插件 id>/board`。每摆一次就新建一个视图，所以可以带不同的 `info.panel` 出现多次，比如两个看板各看一台机器。`info.panel` 经 `deserialize(data)` 交给视图，`serialize()` 写回；没给就是 `null`，面板要能照常画（比如看板不带参数就看所有机器）。
- **插件入口不显示。** `entry` 默认导出的视图是插件的根：宿主挂载它，它在 `init()` 里注册面板、起后台订阅，但它不进布局。原来「入口视图就是那个 tab」的写法取消，`plugin:<id>` 这个名字也取消，现有插件（技能，以及示例仓库里的看板、队伍）一次改过来。这和 gpui-shell 自己的模型一致：应用根 + `register_panel`。
- 原来的 `smelt.tools` 取消：工具面板就是布局里一个普通的 `TabPanel`，见 `docs/workspace-layouts.md`。

**插件的面板清单：`smelt.json`**

gpui-shell 没有「列出某个插件注册了哪些面板」的接口，上游最新的 main 也没有，是有意的：它的注册表只管按名字建。`gpui-shell.json` 又拒收未知字段，放不进去。宿主却要在不跑脚本的情况下知道一个插件有哪些面板：设置页要列、命令面板要能「添加面板」、布局里写的插件没装要能说清楚。所以插件目录里另放一份 smelt 自己的清单：

```json
{ "panels": [{ "name": "board", "title": "看板" }] }
```

- `name` 和 `register_panel` 的第一个参数一致，布局里写 `shell:<id>/<name>`。不能为空、不能带 `/`、不能重复。`title` 是标签上的名字，必填。
- 数组保留顺序，命令面板的「添加面板」按这个顺序列。没有 `smelt.json` 就是没有面板，只有根（比如只起后台任务的插件）。清单坏了插件照样挂载，没有面板，设置页显示原因。
- 布局里写了、插件没装或这次不再声明的面板，画一块「插件未安装」的占位，存档时原样写回，不静默消失。
- 和 VS Code 的 `contributes.views` 加 `registerWebviewViewProvider` 是同一个路数：清单说有什么，代码说怎么画。herdr 一个 mod 只有一块，`mod.json` 里写 `place`；我们一个插件可以有多块，位置交给布局。

**插件的命令**

`smelt.json` 里还可以声明命令：

```json
{ "commands": [{ "name": "next-needs-you", "title": "下一个等你的智能体", "key": "cmd-shift-j" }] }
```

- `name` 规矩和面板名一样（不能为空、不能带 `/`、不能重复），`title` 必填，是命令面板里的名字（前面带插件名）。`key` 可选，gpui 写法。
- 插件在根视图的 `init()` 里循环 `await next_command()`，兑现成命令名。宿主不回调脚本，命令和订阅一样是一个异步函数；插件没在等时命令先排着（最多 16 条，多了丢最早的），一个插件只能有一处在等。
- 快捷键守和用户改键同样的规矩：只收一个按键，要带 ⌘（或者是 F 键），不能是保留键，不能撞上 smelt 的快捷键（按用户当前的键位）、组件的键、先加载的插件的键。撞上就不装，设置 → 插件里这个插件下面写原因；用户录键撞上插件的键时也说是哪个插件的。插件的键和 smelt 自己的键是键表里同一段，改键、重新加载插件时一起换。绑在 `Workspace` 上。
- 反过来，插件能执行命令：`commands()` 列出 smelt 能改键的那些（`split_beside`……）和各插件声明的（`<插件 id>/<命令名>`），带分组名（smelt 的按快捷键设置页分，插件的是插件名）和眼下绑的键；每次重装键（改键、重新加载插件）主题 `commands` 变，插件用 `changed("commands", since)` 等。`run(id)` 执行：smelt 自己的命令和按键一样按当前焦点派发，「编辑与导航」那几条（保存文件、上下一个差异）要焦点在文件或差异里才起作用；插件的命令交给那个插件。样例：示例仓库的 `keys/`（快捷键速查），列出全部命令和键，点一行执行。
- 布局的命令（`layout.select {panel}`、`layout.zoom {panel}`、`layout.add {panel, to?}`、`layout.focus {id}`、`layout.toggle_dock {dock}`、`layout.switch {layout}`、`layout.reset`、`layout.copy {layout?}`）按带参数的写法做：`run("layout.select", { panel: "smelt.git" })`。参数形状不对时 `run` 报错，面板、布局不在了在工作台里提示。`commands()` 里只列不带参数的两条；表见 `docs/workspace-layouts.md` 的「命令」。
- `layout()` 给出当前布局：id 和名字，布局里的面板（按树的先后：面板名、标题、看不看得见、所在组是不是放大着），贴着窗口左上角、右上角的面板名，红黄绿按钮要让多宽（`lights`，全屏和 Windows 下是 0），几块舞台（`stages`：id、`accepts`、有没有焦点、显示着哪个页面）；变了发主题 `layout`。会话显示在哪块舞台看 `sessions()` 的 `stage`，换焦点用 `run("layout.focus", { id })`。标签条由皮肤画，插件面板贴角时自己让开红黄绿按钮。
- `git()` 给当前项目根目录的分支、跟踪的远端、领先落后几个提交、改动文件数、stash 数；不是仓库、还没读到时是 null。smelt 收到文件变化就重读，变了发主题 `git`，插件不用自己跑 git。只有当前项目一份，侧栏每个项目一份的等有样例。
- 相对时间（「25m」）插件自己在画的时候拿 `Date.now()` 和 `updated_at` 算，不另开定时器，和 smelt 自己的侧栏一样：每次因为别的事重画时更新，空闲时可能停在旧值。
- 还没有：用户给插件命令改键；连按（tmux 那种前缀键）；不带 ⌘ 的键（⌃ 组合留给终端和输入框，要放开得先想清楚终端里怎么让）。

**插件的身份**

挂载每个插件前，宿主给它建一份自己的 Policy 换成默认的（`plugins::plugin_policy`）：应用 id 是插件 id，`register_panel` 按它给面板起名，两个插件都叫 `board` 也不会撞；`smelt-fs`、`smelt-workspace` 按插件各建一份，宿主因此知道是谁在调，`next_command()` 只取发给自己的命令。权限大家一样。面板类注册时记下注册它的 Policy，之后再建的面板照样是这个插件的。全部挂完换回一份空的，插件以外的视图不冒用最后一个插件的身份。

**建面板**

- 内置组件和插件面板一样经 gpui-base 的注册表建（`register_panel`），`DockArea::load` 按名字建。内置的需要工作台的句柄，注册时带上；同一个内置面板的实体缓存着，切布局时复用。
- 插件面板就是 gpui-shell 的脚本面板，直接放进 Dock，不再包一层。它没有标题，标签上的名字由皮肤按注册名查 `smelt.json` 里声明的 `title`。
- 插件删了以后它注册过的类还在运行时里（注册表没有注销）。所以每次 `mount_all` 都比较上一次和这一次声明的面板，消失的名字改注册成「插件未安装」的占位，占位原样保留它的 `info.panel`；插件装回来再注册一次就盖回去。
- 插件重新加载后，已建的插件面板还在跑旧代码：工作台 `dump` 一次再 `load` 回去，插件面板按新脚本重建，拆分宽度、选中的标签不动。

**只能整块换，不开槽位，不做装饰**

内置组件里面画什么归组件，布局不能关掉它的一部分（见 `docs/workspace-layouts.md` 的「边界」）。插件要换就整块换（会话列表、工具面板）；舞台不能换，它的标题胶囊也不能单独换。插件可以在舞台旁边摆自己的面板，读 `sessions()` 里 `stage` 是这块舞台的会话和 `git()` 画。不开槽位：gpui-shell 的面板只在建的时候拿到 `info.panel`，宿主没法更新，而且插件本来就读得到当前会话。原来想的「装饰」（插件给数据、内置组件照着画）也不做：插件能画的东西受内置组件限制，每多一种画法就要宿主多认一种数据。会话列表这类能整块换掉的，直接整块换。

### 3. 布局

就是 `docs/workspace-layouts.md`。布局文件和存档都是 gpui-base Dock 的官方格式 `DockAreaState`：怎么切、哪几个面板叠成一组、选中哪个。面板的配置在它自己的 `info.panel` 里；外观归皮肤和主题，不写进布局。顶栏、状态栏这类周边都是放了插件面板的普通一格。

插件可以带布局：插件目录下的 `layouts/*.json`，id 是 `<插件 id>/<文件名>`。导入插件时它带了布局就直接换上（多套时用按 id 排第一的），装上就生效；命令面板里随时换回别的布局。删掉插件时当前布局是它带的，回到默认布局。布局的名字（和要不要连带换主题）以后写在插件的 `smelt.json` 里，官方格式里没有这些字段。

### 4. 外观

- **主题**：沿用 gpui-kit 标准主题文件（一个文件一个系列，`themes` 里可以有明暗几款，能写配色、`radius`、`radius.lg`、`shadow`、字号）。插件目录下 `themes/*.json` 都认，按文件名排；主题是数据，插件脚本加载失败也照样装。和内置主题重名的不装（插件不能顶替内置主题，免得用户选的「Ayu Dark」被悄悄换掉），插件之间重名按加载顺序先到先得；没装上的、文件坏了的，原因写在设置 → 插件里那个插件下面。插件带的主题不进组件库的主题注册表（那张表只增不删，插件删了主题还在），smelt 自己存一份，重新加载插件时整份换掉。设置的主题下拉里内置的在前，插件的接在后面，系列名是插件名。
- **背景不写在布局上**：v1、v2 让布局给区域写背景图，v3 用官方格式，没有这个字段，先去掉。要各区域自己的背景图，做成皮肤的一部分（主题或设置），不进布局。
- **跟着布局走**（v3 暂时没有，待插件的 `smelt.json` 给布局写名字时一起做）：布局可以连带一个主题，换到这套布局就把它写进设置，Traveler 这种整套风格才装上就是那个样子。主题只有设置里那一个，用户之后在设置里另选照常生效，最后一次操作说了算；不搞「布局压过设置」，那样屏幕上的和设置页显示的会是两个主题。存着的主题找不到了（插件删了）就套同明暗的默认主题，名字不动，插件装回来又是它。
- 字体、字号仍归设置页：那是用户的阅读习惯，不跟着包走。

### 5. 包

分享单位。一个目录，根上放 smelt 自己的清单 `smelt-package.json`，写明：

- `id`、`name`、`version`、作者、来源地址；
- 需要的 smelt 版本和宿主接口版本；
- 贡献：`layouts/`、`themes/`、`components`（每个组件指向一个 gpui-shell 应用目录）、命令、技能；
- 依赖的其他包。gpui-shell 清单已经支持按 git 地址依赖，组件之间的脚本依赖照用它。

规则：

- 没有脚本的包（只有布局、主题）也是包。用户 `~/.smelt/layouts/` 里散放的文件仍然直接认，相当于一个本地匿名包。
- 装到 `~/.smelt/packages/<id>/`，整包装、整包删。id 撞了提示改名，不覆盖。
- 装上就生效：包带了布局就直接换上（外观跟着布局），提示怎么换回去。装了不用、要用户再去找开关，等于没装好。
- 现在的 `~/.smelt/plugins/` 迁成包：一个只贡献一个组件的包。迁移一次做完，不留两套目录。

### 6. 信任

现在的决定是插件当可信代码、不设权限，开放生态也先不改。改起来代价大，而 gpui-shell 的隔离也不完整。所以要老实告诉用户，装包时宿主列出：

- 来源（git 地址或文件）、作者、版本；
- 带不带脚本。带脚本的写明「可以读写你的文件、执行命令」；
- 声明了哪些网络主机。

只有布局和主题的包没有执行风险，可以直接装。签名、审核、按包授权放到真有公共画廊以后再说。

### 7. 跨端

界面贡献（组件、布局、主题）只在桌面生效：手机端是 Flutter，跑不了 gpui-shell。能力贡献（技能、MCP、自动化的触发器和连接器）走 smeltd 和 Pi，手机和远端机器都能用。一个包可以两样都带，手机上只装能力那一半。

### 8. 给智能体

- `smelt package check <目录>`、`smelt layout check <文件>`：加载一次，报出和桌面一致的错误。
- `smelt shot`：截当前窗口，智能体改完界面能自己看效果。
- 技能文档跟着版本走：宿主接口、清单格式、组件名单，以及一个完整样例包。

## 不做

- 不为内置组件写 JS 版。
- 不建插件市场。分享先用 git 仓库和目录导入；画廊以后做成一份静态索引，指向各个仓库。
- 不做第二套插件运行时。界面插件只有 gpui-shell。
- 不做按插件授权，理由见「信任」。

## 分阶段

每一阶段都拿一个真实样例验收，不靠想象补接口。

1. **布局**（本分支）：声明文件、切换、恢复默认。`smelt layout check` 归第 8 步。
2. **模型和订阅**（#261、#258）：补齐会话、项目、机器字段和订阅，加上常用操作。样例：状态看板，再加一个替掉 `smelt.sessions` 的 Traveler 式左栏。验收：左栏全部信息来自宿主接口，空闲时没有唤醒。
   - 已做：`changed(topic, since)`。宿主不能回调脚本，所以订阅是一个异步函数：主题的版本号不等于 `since` 时兑现，插件在循环里 await 它。主题有 `context`、`sessions`、`machines`、`commands`。会话加了 `kind`、`unread`、`project`、`machine`、`model`、`context`、`updated_at`、`turn_started_at`。`machines()` 给出侧栏里的机器和各自的项目（显示名、是否打开、置顶、当前）。操作加了 `close_session`（和点 × 一样，正在跑的先确认）、`select_project`。技能面板去掉了每秒一次的检查。
   - 快照由工作台的 `publish_to_plugins` 统一发布，三处调用：提醒和状态变化（`sync_notification_surfaces`）、侧栏状态落盘（`save_state`）、机器列表变化。只比较内存，没变不动版本号。
   - 样例：示例仓库的 `kanban/`（#258），三列就是宿主的三态，不往细里猜；示例仓库的 `layouts/kanban-below.json` 把它放在舞台下面。
   - 新建会话：侧栏「+」的选项和创建拆成了能单独调用的函数（`session_list::new_session_sections` / `launch_new_session`），弹层和插件共用。`new_session_options(machine)` 是异步的：远程机器先去那台机器读一次装了什么；`new_session(machine, root, key)` 按 key 现查再建，选项已经没了就不建。选项不进快照，插件要显示时现取。
   - 当前项目：`context()` 加了 `project`（机器 + 根目录，不管本机远程），`project_root` 仍只在本机项目时有值。原来宿主在远程项目上把所有插件面板都换成「只支持本机项目」的提示，现在不拦了，插件自己看：技能面板在远程项目上照常列本机技能，加一行说明；看板、队伍不受影响。当前项目也改由 `publish_to_plugins` 发布，不再在两个 render 里写。
   - 样例：示例仓库的 `party/`（Traveler 式左栏，但不照抄它的画风）：机器 → 项目 → 智能体卡片，头像框颜色是状态，体力条是上下文剩余（没报用量不画），项目名点了切项目，「+」现取选项起会话。示例仓库的 `layouts/party-left.json` 把它放进左栏，原来的会话列表留作第二个标签。
   - 推理强度：会话加了 `effort`（`{ value, name }`，档位 id 和显示名）。哪个配置项算推理强度按 agent 定（Claude 的 `effort`、Codex 的 `reasoning_effort`、Pi 的 `thought_level`），用户刚选、agent 还没确认的按刚选的算。只有对话有；终端会话里跑的 CLI 不告诉 smelt 它的档位，总是 null，模型和上下文用量也一样。
   - 一轮中途的变化：对话的模型、推理强度、上下文用量变了而这次快照不用落盘时，对话发 `SummaryChanged`，工作台只重发会话快照，不存盘。原来插件要等下一次状态变化才看到新的上下文用量。
   - 操作加了 `open_settings(page?)`：不给 page 和 ⌘, 一样，给了就切到那一页（加机器是 `remote`）。左栏整块换掉以后，设置和加机器的入口由插件自己画。
   - 命令和快捷键：见「插件的命令」。样例：Traveler 的「下一个等你的智能体」（⌘⇧J），跳到正看着的会话之后第一个等你的。
   - 待做：额度；项目的 git 摘要（要后台取，不能在发布快照时现算）；新建选项里的常用项第一次取时可能还没从运行时读回来（和侧栏弹层一样，读回来之前按没有置顶排）。
3. **组件统一**：见「组件注册」。分两块，各自能验收：
   - 插件身份、插件面板、面板自己的参数；入口不再显示，现有插件改成注册面板。样例：看板注册 `board`，一套布局放两块，各看一台机器。
     - 已做：`smelt.json` 面板清单；挂载前换应用名；插件面板带占位和重建（v3 起不再包外层 `PluginPanel`）；技能（`skills`）、看板（`board`，参数 `machine` 只看一台机器）、队伍（`roster`）改成注册面板；示例仓库的 `layouts/two-boards.json` 摆两块看板（本机、全部机器）。
   - 工具面板并入布局：取消 `smelt.tools` 和插件槽位，文件、变更、历史和插件都是普通面板；标签栏由 smelt 的 Dock 渲染器画（角标、窗口拖动区）；Dock 是开合、大小、拆分、选中标签的唯一运行时来源，变化时按布局落盘，取消每帧对齐（`align_shell_dock`）。旧的 `tool_panel_*`、`stage_cover`、`sidebar_open`、`sidebar_w` 列删掉，不迁数据。验收：换布局、拖宽、切标签、重启后都还原，空闲时没有重画。
     - 已做（v3 又改过：`plugin:*` 换成「添加面板」，停靠区开合去掉）：`plugin:*` 展开没摆到别处的声明面板，默认右栏是文件 / 变更 / 历史 / `plugin:*`；`ToolPanelTab`、`StageCover`、每帧对齐和宽度那套都删了，「放大」就是 Dock 的标签组放大；「亮出组件」= 展开所在停靠区再 `select_panel`；状态存 `workspace_layout_state`，按内容去重；启动时布局找不到或坏了用默认并提示，不改写 `layout_id`。标签栏、标题带、窗口外框的做法和不接 `ShellRoot` 的原因见 `docs/workspace-layouts.md` 的「窗口外框」。
     - 顶栏（布局的 `top`）做过一版没提交：它是 Dock 外面的又一个特例。v3 里顶栏就是 `center` 树里一格插件面板。
4. **外观**：用户主题和包里的主题，加上区域背景图和节点的边框、底色、圆角。样例：Traveler 的两张背景。
   - 做过（v1、v2，v3 去掉）：布局区域背景（`background`），舞台那块写了就盖过设置里的背景图；会话列表、舞台的对话和终端、文件树、插件面板在有背景的区域里不铺实底。
   - 已做：插件带主题（`themes/*.json`），设置页主题下拉列出插件的主题。样例：Traveler 的「旅人·夜」「旅人·昼」。布局指定主题（`theme`）做过，v3 的官方格式里没有，挪到插件 `smelt.json`。
   - 待做：用户自己的主题目录；舞台上的智能体、自动化、能力库、桌面页还是实底；设置页给当前布局的区域挑图（不写文件）。
5. **布局 v3：官方格式**：布局文件和存档是 `DockAreaState`，整个工作台是一个 `DockArea`，宿主只注册面板、`load` 文件、提供皮肤；存档是 `dump()`；不写尺寸、不做收起；宿主用 `layout()` 告诉插件谁贴着窗口哪个角；默认布局是嵌在程序里的同格式文件。设计见 `docs/workspace-layouts.md`。样例：Traveler 顶栏是 `center` 树里一格，示例仓库加一个状态栏。验收：默认布局下和原来一样分三栏，一张截图的结构只靠布局文件和插件就能拼出来（会话并排除外）。
6. **命令化**：见「命令」。内置的按钮、快捷键、命令面板、插件走同一套带参数的命令。样例：插件里的「新建项目」「加机器」按钮。
7. **周边交给插件**：`layout()` 给面板和看得见没有，插件能自己画切换按钮；`git()` 给当前项目的 git 摘要。样例：示例仓库的状态栏显示分支。
8. **布局补全**：布局文件变化时重新加载（事件驱动）、`smelt layout check`、JSON Schema、截图命令、设置里的布局页。
9. **包**（#259）：清单、导入、风险展示、版本检查，把 `~/.smelt/plugins/` 迁过来。样例：把前面几步做的 Traveler 打成一个包，在另一台机器上导入。
10. **会话并排**：一个标签里放几个会话（「一个标签 = 一个会话」改成「一个标签 = 一组分屏」），每个分屏一条顶条（到时候再看要不要在舞台里开槽位）。布局已经能摆几块舞台、按 `accepts` 各放一样东西（`workspace-layouts.md` 的「几块舞台」），这一步要的是同一块舞台里分屏放几个会话。要改会话模型，可能动表结构，单独出设计、先确认。
11. **画廊**：等有外部作者再说。
