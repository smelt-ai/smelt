# 插件平台：整个工作台可定制、可分享

状态：架构草稿。第 2 步已开工：`smelt-workspace` 有了 `changed()` 订阅、更全的会话字段、机器和项目，以及关会话、切项目；能列新建选项、起会话；会话看板（`plugins/kanban`）和左栏样例「队伍」（`plugins/party`）只用这些接口。第 3 步改成「组件统一」：先前把工具面板页签拆出来单独摆，是在三套放置系统之间打补丁，停下改底层，设计见「组件注册」和 `docs/workspace-layouts.md`。总任务 #257；布局 #260（`docs/workspace-layouts.md`，`feat/workspace-layouts` 上有粗版本），看板 #258，分享导入 #259，事件订阅 #261。

## 目标

开放生态：第三方不改 Rust、不重新编译 smelt，就能

1. **加功能**：新面板、新命令、新的智能体技能。
2. **换掉任意一块界面**：会话列表、标签栏、状态栏都能换成自己画的。
3. **换外观**：配色、圆角，各区域自己的背景图。
4. **打包分享**：上面这些合成一个包，别人一次装好、随时切回默认。

参照物是 herdr 画廊里的 Traveler：左栏像素风项目卡和智能体卡（模型、状态、HP/SP），标签带头像，侧栏和舞台各一张背景图。这一整套在 herdr 里是布局 + 若干 mod + 外观，装一个包就有。

## 现状

扩展点各管一摊，没有统一的包和接口：

| 层 | 现在能扩展什么 | 缺什么 |
|---|---|---|
| 界面插件（gpui-shell，JS + QuickJS，GPUI 原生绘制） | 工具面板里的 tab；本分支起能进布局任意位置；能画图片 | 宿主接口有 `smelt-fs`、`smelt-workspace`：当前项目、会话快照（类型、智能体、三态、未读、目录、所属项目、机器、模型、上下文用量、时间）、机器和项目、`changed()` 订阅、打开和关闭会话、切项目、新建会话、选目录；一个插件只能贡献一个面板，工具面板、插件槽位和布局是三套放置系统 |
| 布局 | 本分支：声明文件、切换、恢复默认 | 只认三大块，内部不能再拆 |
| 外观 | 设置页：22 套内置主题、整窗背景色/图、透明度、字体 | 主题编进程序；背景图只有一张整窗的 |
| 智能体（Pi） | 内置技能、MCP、Pi 扩展（如压缩调优插件） | 和界面插件是两套安装方式 |
| 守护 / CLI | Control API v3、`smelt` 命令、事件总线、自动化 | 界面插件用不上事件总线 |

## 分层

```
┌ 包（分享单位）─ 清单 + 贡献 + 资源 ───────────────────────────┐
│  布局     外观（主题 + 背景图等资源）   组件（脚本）   命令   技能 │
└──────────────┬──────────────────────────┬─────────────────────┘
               │ 引用组件名                │ 调宿主接口
┌ 组件注册 ─────┴─────┐      ┌ 宿主接口（带版本）─────────────────┐
│ smelt.* 内置（Rust） │      │ 快照 + 订阅 + 操作                 │
│ plugin:<包>/<组件>   │      │ 内置界面用到的数据，插件都拿得到     │
└─────────────────────┘      └──────────────┬────────────────────┘
                                            │
                              工作台模型（客户端库 + smeltd 推送）
```

自下而上：

### 1. 工作台模型和宿主接口：接口对等

**原则：内置界面画得出来的，插件都拿得到。** 内置组件和插件读同一份模型，只是一个用 Rust 画、一个用 JS 画。做不到对等，插件就只能「在旁边加」，永远替不掉内置组件；生态卡在这里，不在布局。

- **快照 + 订阅 + 操作**三件套。订阅按主题分（项目、会话、机器、通知……），推送的是「变了」加新版本号，插件再读快照（#261）。空闲时没有唤醒。
- 模型字段按真实组件需要来补，不一次铺满。Traveler 那一栏要：会话的智能体、模型和推理强度、细分状态、上下文用量、额度；项目列表和每个项目的 git 摘要（未提交、未推送）；机器列表和在线状态；新建会话、关会话、切项目。
- 接口带版本：`smelt-workspace` 这类模块有主版本号，插件在清单里写需要的版本，不满足就不加载并说清楚原因。加字段不升版本，改语义、删字段才升，能不升就不升。
- 每个版本自动生成类型文件（gpui-shell 已经会往插件目录写 `gpui-kit.d.ts`，宿主模块的类型跟着写），智能体照类型改插件。

### 2. 组件注册

布局里引用的每个名字都是一个组件。**放到界面上只有一条路：布局树。** 没有第二套「工具面板页签」「插件槽位」。

**名字**

- **内置**：`smelt.sessions`、`smelt.stage`、`smelt.files`、`smelt.git`、`smelt.history`。集合是封闭的，Rust 里是一个枚举；内置组件**不改写成 JS**，终端、对话流这类重件留在 Rust，性能和输入法细节都在那里。
- **插件面板**：`plugin:<插件 id>/<面板>`，插件往布局里放东西只有这一种。插件先在 `smelt.json` 里声明面板（见下面「插件的面板清单」），再在 `init()` 里调 gpui-shell 的 `DockArea.register_panel("board", Board)`，注册进 gpui-kit 的全局面板注册表，名字是 `shell:<插件 id>/board`。每摆一次就新建一个视图，所以可以带不同 `props` 出现多次，比如两个看板各看一台机器。props 经 `deserialize(data)` 交给视图；没给就是 `null`，面板要能照常画（比如看板不带参数就看所有机器）。
- **插件入口不显示。** `entry` 默认导出的视图是插件的根：宿主挂载它，它在 `init()` 里注册面板、起后台订阅，但它不进布局。原来「入口视图就是那个 tab」的写法取消，`plugin:<id>` 这个名字也取消，现有插件（技能、看板、队伍）一次改过来。这和 gpui-shell 自己的模型一致：应用根 + `register_panel`。
- 原来的 `smelt.tools` 取消：工具面板就是布局里一个普通的标签组，见 `docs/workspace-layouts.md`。

**插件的面板清单：`smelt.json`**

gpui-shell 没有「列出某个插件注册了哪些面板」的接口，上游最新的 main 也没有，是有意的：它的注册表只管按名字建。`gpui-shell.json` 又拒收未知字段，放不进去。宿主却要在不跑脚本的情况下知道一个插件有哪些面板：设置页要列、没摆进布局的要有个去处、布局写错了面板名要能说清楚。所以插件目录里另放一份 smelt 自己的清单：

```json
{ "panels": [{ "name": "board", "title": "看板" }] }
```

- `name` 和 `register_panel` 的第一个参数一致，布局里写 `plugin:<id>/<name>`。不能为空、不能带 `/`、不能重复。`title` 是标签上的默认名字，必填。
- 数组保留顺序，没摆进布局的面板按这个顺序排。没有 `smelt.json` 就是没有面板，只有根（比如只起后台任务的插件）。清单坏了插件照样挂载，没有面板，设置页显示原因。
- 声明了但代码没注册、注册了但没声明，都只在摆出来时画一块说明，不静默消失。
- 和 VS Code 的 `contributes.views` 加 `registerWebviewViewProvider` 是同一个路数：清单说有什么，代码说怎么画。herdr 一个 mod 只有一块，`mod.json` 里写 `place`；我们一个插件可以有多块，位置交给布局。

**插件的身份**

挂载每个插件前，宿主用 `gpui_shell::policy::update_default(|p| p.with_application(id))` 把应用 id 设成插件 id。视图出生时定下这份策略，`register_panel` 按它给面板起名，两个插件都叫 `board` 也不会撞。宿主模块、权限仍然共享。

**建面板**

- 内置组件由宿主直接建，需要工作台的句柄，不进全局注册表。
- 插件面板经 `PanelRegistry::build_panel` 建。能不能建看**当前挂着哪些插件**，不看注册表：插件删掉以后它注册过的类还在运行时里，照样建得出来。
- 上游的脚本面板只实现了行为，没有标题（放进我们的 Dock 会显示 `shell:…` 内部名）。宿主在外面包一层 smelt 面板，提供标题、错误占位，把 `set_active` / `on_removed` 转给里面。标题默认是 `smelt.json` 里声明的 `title`，布局里可以写 `title` 覆盖：同一个面板摆多次时本来就要分得清。
- 插件重新加载后，已建的插件面板还在跑旧代码，全部重建一次：外面那层 smelt 面板不换（Dock 不用重搭，停靠区开合、宽度不动），只换里面的脚本面板。
- 外层面板被 Dock 移走时（换布局）不让脚本释放：换布局时同一个面板会先移走再放进新的一套。真不用了（新布局里没有、插件删了、重建）才调脚本面板的 `on_removed`，让 gpui-shell 释放它留着的句柄。

**开放的另两条路**

- **装饰**：不想整块替换时，插件给内置组件提供数据，内置组件照着画。例如给会话指定头像、颜色、徽标，会话列表照着画。Traveler 的头像走这条路就够了。
- **拆细**：等有真实需求再把内置大块拆开。现在舞台里只有一段对话，没有标签栏和状态栏可拆；侧栏要拆也等有样例再说。

### 3. 布局

就是 `docs/workspace-layouts.md`。布局只管排布、只引用组件名，不放外观。

### 4. 外观

- **主题**：沿用 gpui-kit 标准主题文件，用户和包都能带。加载规则和布局一样：用户的、包里的、内置的按顺序，同名先到先得；文件坏了列出原因。
- **smelt 扩展段**：主题文件里加一段 smelt 自己的字段，按组件名给背景图和透明度，比如 `"backgrounds": {"smelt.sessions": "img/castle.png", "smelt.stage": "img/map.png"}`。图片路径相对主题文件。格式由我们定义、带版本，不认识的字段报错。
- 字体、字号仍归设置页：那是用户的阅读习惯，不跟着包走。

### 5. 包

分享单位。一个目录，根上放 smelt 自己的清单 `smelt-package.json`，写明：

- `id`、`name`、`version`、作者、来源地址；
- 需要的 smelt 版本和宿主接口版本；
- 贡献：`layouts/`、`themes/`、`components`（每个组件指向一个 gpui-shell 应用目录）、命令、技能；
- 依赖的其他包。gpui-shell 清单已经支持按 git 地址依赖，组件之间的脚本依赖照用它。

规则：

- 没有脚本的包（只有布局、主题）也是包。用户 `~/.smelt/layouts/` 里散放的文件仍然直接认，相当于一个本地匿名包。
- 装到 `~/.smelt/packages/<id>/`，整包装、整包删。id 撞了提示改名，不覆盖。
- 装包不自动换当前布局和外观。装完列出它带来了什么，用户自己选。
- 现在的 `~/.smelt/plugins/` 迁成包：一个只贡献一个组件的包。迁移一次做完，不留两套目录。

### 6. 信任

现在的决定是插件当可信代码、不设权限，开放生态也先不改。改起来代价大，而 gpui-shell 的隔离也不完整。所以要老实告诉用户，装包时宿主列出：

- 来源（git 地址或文件）、作者、版本；
- 带不带脚本。带脚本的写明「可以读写你的文件、执行命令」；
- 声明了哪些网络主机。

只有布局和主题的包没有执行风险，可以直接装。签名、审核、按包授权放到真有公共画廊以后再说。

### 7. 跨端

界面贡献（组件、布局、主题）只在桌面生效：手机端是 Flutter，跑不了 gpui-shell。能力贡献（技能、MCP、自动化的触发器和连接器）走 smeltd 和 Pi，手机和远端机器都能用。一个包可以两样都带，手机上只装能力那一半。

### 8. 给智能体

- `smelt package check <目录>`、`smelt layout check <文件>`：加载一次，报出和桌面一致的错误。
- `smelt shot`：截当前窗口，智能体改完界面能自己看效果。
- 技能文档跟着版本走：宿主接口、清单格式、组件名单，以及一个完整样例包。

## 不做

- 不为内置组件写 JS 版。
- 不建插件市场。分享先用 git 仓库和目录导入；画廊以后做成一份静态索引，指向各个仓库。
- 不做第二套插件运行时。界面插件只有 gpui-shell。
- 不做按插件授权，理由见「信任」。

## 分阶段

每一阶段都拿一个真实样例验收，不靠想象补接口。

1. **布局**（本分支，粗版本已有）：声明文件、切换、恢复默认。拖出来的状态归第 3 步，`smelt layout check` 归第 5 步。
2. **模型和订阅**（#261、#258）：补齐会话、项目、机器字段和订阅，加上常用操作。样例：状态看板，再加一个替掉 `smelt.sessions` 的 Traveler 式左栏。验收：左栏全部信息来自宿主接口，空闲时没有唤醒。
   - 已做：`changed(topic, since)`。宿主不能回调脚本，所以订阅是一个异步函数：主题的版本号不等于 `since` 时兑现，插件在循环里 await 它。主题有 `context`、`sessions`、`machines`。会话加了 `kind`、`unread`、`project`、`machine`、`model`、`context`、`updated_at`、`turn_started_at`。`machines()` 给出侧栏里的机器和各自的项目（显示名、是否打开、置顶、当前）。操作加了 `close_session`（和点 × 一样，正在跑的先确认）、`select_project`。技能面板去掉了每秒一次的检查。
   - 快照由工作台的 `publish_to_plugins` 统一发布，三处调用：提醒和状态变化（`sync_notification_surfaces`）、侧栏状态落盘（`save_state`）、机器列表变化。只比较内存，没变不动版本号。
   - 样例：`plugins/kanban`（#258），三列就是宿主的三态，不往细里猜；`layouts/kanban-below.json` 把它放在舞台下面。
   - 新建会话：侧栏「+」的选项和创建拆成了能单独调用的函数（`session_list::new_session_sections` / `launch_new_session`），弹层和插件共用。`new_session_options(machine)` 是异步的：远程机器先去那台机器读一次装了什么；`new_session(machine, root, key)` 按 key 现查再建，选项已经没了就不建。选项不进快照，插件要显示时现取。
   - 当前项目：`context()` 加了 `project`（机器 + 根目录，不管本机远程），`project_root` 仍只在本机项目时有值。原来宿主在远程项目上把所有插件面板都换成「只支持本机项目」的提示，现在不拦了，插件自己看：技能面板在远程项目上照常列本机技能，加一行说明；看板、队伍不受影响。当前项目也改由 `publish_to_plugins` 发布，不再在两个 render 里写。
   - 样例：`plugins/party`（Traveler 式左栏，但不照抄它的画风）：机器 → 项目 → 智能体卡片，头像框颜色是状态，体力条是上下文剩余（没报用量不画），项目名点了切项目，「+」现取选项起会话。`layouts/party-left.json` 把它放进左栏，原来的会话列表留作第二个标签。
   - 待做：推理强度、额度；项目的 git 摘要（要后台取，不能在发布快照时现算）；新建选项里的常用项第一次取时可能还没从运行时读回来（和侧栏弹层一样，读回来之前按没有置顶排）。
   - 已知缺口：会话快照在对话发 `Changed`、守护状态推送、提醒变化时才重发。一轮中途只更新了上下文用量时，插件要等下一次这类事件才看到新值。
3. **组件统一**：见「组件注册」。分两块，各自能验收：
   - 插件身份、插件面板、布局里的 `props` 和 `title`；入口不再显示，现有插件改成注册面板。样例：看板注册 `board`，一套布局放两块，各看一台机器。
     - 已做：`smelt.json` 面板清单；挂载前换应用名；外层 `PluginPanel` 经 `PanelRegistry::build_panel` 建、带占位和重建；技能（`skills`）、看板（`board`，`props.machine` 只看一台机器）、队伍（`roster`）改成注册面板；`layouts/two-boards.json` 摆两块看板（本机、全部机器）。
     - 这一块还留着 `smelt.tools`：没摆进布局的声明面板各占工具面板的一个页签（槽位换成按面板记，存档里是 `<插件 id>/<面板>`），第二块换成 `plugin:*` 时一起删。这些页签不在 Dock 里，收不到 `set_active`。
   - 工具面板并入布局：取消 `smelt.tools` 和插件槽位，文件、变更、历史和插件都是普通面板；标签栏由 smelt 的 Dock 渲染器画（角标、窗口拖动区）；Dock 是开合、大小、拆分、选中标签的唯一运行时来源，变化时按布局落盘，取消每帧对齐（`align_shell_dock`）。旧的 `tool_panel_*`、`stage_cover`、`sidebar_open`、`sidebar_w` 列删掉，不迁数据。验收：换布局、拖宽、切标签、重启后都还原，空闲时没有重画。
4. **外观**：用户主题和包里的主题，加上按组件的背景图和节点的边框、底色、圆角。样例：Traveler 的两张背景。
5. **布局补全**：布局文件变化时重新加载（事件驱动）、`smelt layout check`、截图命令。
6. **包**（#259）：清单、导入、风险展示、版本检查，把 `~/.smelt/plugins/` 迁过来。样例：把前面几步做的 Traveler 打成一个包，在另一台机器上导入。
7. **装饰**：会话头像、颜色、徽标；宿主接口补推理强度、额度、项目的 git 摘要。
8. **画廊**：等有外部作者再说。

第 2 步是关键：接口对等做不到，后面几步都是空架子。
