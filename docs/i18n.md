# 界面语言（i18n）

桌面端的界面文字按用户选的语言显示。现在带英文（`en`）和简体中文（`zh-CN`），文案缺了回落到英文。
用的是 rust-i18n，和 gpui-kit 同一套。

## 机制（插件接口，`smelt-plugin-api/src/locale.rs`）

- 当前语言是 rust-i18n 里的一个全局值，所有 crate 共用。宿主启动时按系统首选语言设一次；内置插件
  「语言」（`plugins/language`）加载时换成用户在「设置 → 通用 → 语言」里选的，选择记在它自己的库里。
- `api::set_locale` 换语言：发 `HostEvent::LocaleChanged`，重画所有窗口。`api::locale()` 读当前语言，
  `api::LOCALES` 是 App 带的语言。
- 登记给宿主、要显示的字（视图、命令、页、布局的标题，菜单项、右键菜单项的字）是 `api::Text`：宿主显示时
  才取，换语言不用重新登记。读登记表得到的 `ViewInfo`、`CommandInfo` 这些是取的那一刻的快照。

## 文案放哪

每个 crate 管自己的字：插件、组件库 `smelt-ui`、宿主 `smelt` 各带一份 `locales/ui.yml`。删掉一个插件，
它的文案跟着走。

```toml
# Cargo.toml
rust-i18n.workspace = true
```

```rust
// crate 根（lib.rs / main.rs）
rust_i18n::i18n!("locales", fallback = "en");
```

```yaml
# locales/ui.yml
_version: 2
list:
  title:
    en: Sessions
    zh-CN: 会话
  empty:
    en: No sessions in %{project}
    zh-CN: "%{project} 里还没有会话"
```

- 键按界面上的区域分层，叶子用 `snake_case`，写清是什么字（`list.empty`、`dialog.delete.confirm`）。
  键只在本 crate 内有效，不用带插件名。
- 每条都写全 `en` 和 `zh-CN`。值以 `%`、`*`、`&`、`!`、`{`、`[`、`"`、`'` 开头，或含 `: `、` #` 的要加引号。
- 一条就是一句完整的话，插值用 `%{name}`。不拿几段译文拼句子，各语言的语序不一样。
- 单复数：英文要区分的，按数量分成两条键（`count.one`、`count.other`），代码里按数量挑。

## 怎么取

```rust
use rust_i18n::t;

// render 里现取：查一次内存里的表，不是 IO。
div().child(t!("list.title").to_string())
Button::new("delete").label(t!("list.delete"))
SettingsRow::new(t!("row.font_size")).description(t!("row.font_size_hint", min = MIN, max = MAX))

// 登记给宿主的标题：跟着语言变的 Text。
ViewSpec { title: text!("view.title"), .. }
contract::OPEN.spec(text!("command.open"), handler)
api::register_commands(OWNER, text!("command.group"), specs, cx)
```

- 键写字面量，测试才查得到；按枚举挑字时每个分支写一个 `t!("…")`。
- 存在视图状态里的字（建好的菜单、预先排好的列表行、缓存的提示）要在 `HostEvent::LocaleChanged` 里重建，
  或者改成 render 里现取。每次打开才建的（搜索条的输入框、一次性的提示）不用管，下次打开就是新语言。
- 设置页的搜索关键词（`SettingsEntry::keywords`）不跟语言走，两种语言的词都写上，用哪种语言搜都找得到。

## 什么不翻

- 日志（`eprintln!`、`app_log`）、`panic!` / `expect` 的话、只给插件作者看的登记错误和接口说明、
  主题文件的解析报错（给写主题的人看）、只给开发者看的调试视图（对话的轨迹窗口）、测试。
- 名字：产品名（Smelt）、智能体名（Claude、Codex）、语言自己的叫法（「English」「简体中文」）。
- 用户和智能体写的内容。
- 运行时（`smeltd`、`smelt-core`）自己说的话：运行时不知道看的人用什么语言，见下一节。
- 日期、数字的本地化格式：还没做。

## 运行时发来的话

运行时不替人措辞，发种类和参数，客户端按自己的语言说。控制调用、自动化的种类和文案在
`smelt-runtime-client`（`src/protocol/reason.rs`、`locales/ui.yml`）；会话状态、提醒里的种类
（`SessionNote`、`TurnFailure`、`ConversationEndReason`、`AttentionKind::label`）在
`smelt-event-protocol`（`src/note.rs`、`locales/ui.yml`），因为线上格式就在那儿。桌面、手机、命令行共用。

- 控制调用的报错带 `reason`（`ControlReason`，按 `kind` 分），运行时用
  `ControlError::because(code, reason)` 发；客户端显示一律用 `ControlError::text()`，不直接读
  `message`。`message` 是运行时按英文说的同一句，给老客户端、日志和比客户端新的种类兜底。
  只新增字段，不升控制协议版本。新种类只往后加，客户端不认识的读成 `Other`，改说 `message`。
- 自动化的配置问题是 `AutomationProblem`：桌面、手机保存前在本地校验，运行时拒绝保存、触发时
  装进 `ControlReason::Automation`，两边说同一句。
- 手机和命令行启动时按系统语言设 rust-i18n 的当前语言；`smeltd` 不设，说英文。
- 命令行（`smelt-cli`）自己的用法、帮助和参数报错在它的 `locales/ui.yml`，`main.rs` 和 lib 共用这一份；
  stdout 的 JSON 只翻给人读的句子（`next` 提示、MCP 预设的 `name`/`summary`），字段名、id、状态值不翻，
  脚本按 id 认东西。
- 自动化运行没成的原因是 `AutomationRunFailure`，存在运行记录的 `error_code` 列；`error` 只存底层
  报错当细节。回合没完成按 `TurnFailure` 细分（`AutomationRunFailure::for_turn`）。客户端显示用 `AutomationRun::error_text()`：有种类按语言说再接上细节，没有种类（旧记录，
  或成功了但 stderr 有输出）原样给 `error`。
- 对话结束的原因是 `ConversationEndReason`，在会话快照的 `end_code` 上（不认识的读成 `Other`）；
  `end_reason` 有种类时是细节，没有种类时是智能体自己报的原话。运行时用 `force_end_because` 记，
  客户端显示用 `ConversationSnapshot::end_text()` / `acp_session::end_text()`。
- 会话列表「待处理」那一行里运行时自己说的话（回合没完成、对话结束）是会话状态上的
  `pending_note`；`pending_question` 照旧是整句（运行时按英文说），给旧客户端兜底，智能体的原话
  也在这里。运行时只存一份（`session_state::PendingLine`），上线时才拆成这两个字段。客户端显示用 `DaemonSessionState::pending_text()`。
- 提醒（`AttentionItem`）的标题按 `kind` 说（`title_text()`），内容有 `note` 时按它说
  （`message_text()`）；`title`、`message` 是运行时按英文写的兜底。
- 推送在运行时里说，按每台手机登记推送时报的语言（`push.register` 的 `locale`，存在
  `push_registration.locale`）用 `SessionNote::text_in` 说；没报语言的旧 App 收英文。
- 驱动线程 panic 发 `ConversationEvent::DriverCrashed`，结束原因记成 `DriverCrashed`，panic 原话当细节。
- 子智能体派发的标题存进对话，由运行时（Rust 和 `agent/` 的 Pi 扩展）算，所以只用智能体给的名字
  （标签、预设名、任务首行）。多项的并行 / 串联组和没名字的都留空，界面按人数和语言说。
- 用户自己能处理的 git 报错也是种类：丢弃前文件又变了、没有远端或推送目标不明、合并冲突、工作树
  （目标已存在、分支在别处检出、有未提交改动或没合进基线不让关、改名时分支变了、定不了上游默认分支）、
  添加仓库（不是仓库根目录、名字占用、URL 不对、克隆失败）。`smelt-git` 的 `GitError`、`WorktreeError`
  带着 `ControlReason`，`smeltd` 原样转发。从智能体开对话（智能体不存在、还不能开对话）同理。
- 只给人排查用的细节照原样显示，不加种类：git、SQLite、进程和管道的原话，更新器的事务细节，
  `pi_rpc` 的底层报错。它们前面那句标题（「安装失败」「推送失败」这类）由客户端按语言说。
- 运行时写进消息流的条目也是种类：回合失败是 `AcpEntry::TurnFailed`（原话 + `TurnHint`，认出来的
  没配 key、key 被拒、连不上、被限流），开新会话的分割线是 `AcpEntry::NewSession`（带时刻，客户端按
  本机时区说）。客户端用 `acp_chat::turn_failed_text`、`AcpEntry::divider_label` 说，文案在
  `smelt-model`。旧运行时发的 `Divider` 是写好的整句，原样显示。客户端开对话、拉快照、看自动化运行详情时
  报自己认的条目版本 `entry_version`（`acp_chat::ACP_ENTRY_VERSION`）；没报的旧客户端，运行时用
  `entry_for_version` 把新种类投成它认的 `Divider` / `Assistant` 英文整句。再加条目种类就升这个版本、补投影，
  不升协议。
- 运行时自己说的一次性提示（不支持插话 / 排队 / 压缩 / 回退、插话或压缩失败、改配置被拒等）是
  `RuntimeNote`，在提示（`AcpNoticeView`）的 `note` 上，运行时发 `ConversationEvent::RuntimeNotice`
  或 `ConfigRejected`；智能体和它的扩展自己的原话仍走 `Notice`，没有种类。客户端显示用
  `AcpNoticeView::display_text()`，`text` 是英文兜底。
- 会话配置里运行时自己写的项（Pi 的权限模式、推理强度、脚本工具）带 `SessionConfigState::smelt`
  （`SmeltConfig`），ACP 的 boolean 配置是开关；客户端一律用 `display_name` / `display_description` /
  `option_label` / `current_label` 说。表单里的是 / 否看 `ElicitOptionView::flag`，用 `display_label`。
  运行时发的名字（`On` / `Off`、`Yes` / `No`、`Full access` 这些）是英文兜底，也是认选项用的原名，
  比较时别用翻过的字。
- 记忆「待确认」的原因存的是种类（`unattended`、`external_content:<工具名>`、`no_provenance` 等，
  Rust 和 `agent/` 的记忆扩展写），客户端用 `MemoryEntry::pending_reason_text()` 说；旧库里写好的
  整句原样显示。
- 其余运行时写的整句（控制报错、安装和版本探测、Pi / ACP 底层报错、审批卡的问题、工具结果、
  hook 上报 `smelt-notify`、`smeltd` 命令行）一律写英文。底层能力库报的细节也一样：`smelt-store`
  （`StoreError`）、`smelt-git`、`smelt-sys`、`smelt-iroh`、`smelt-client-store`、`smelt-client`（更新器的事务细节、`smelt-installer`）、
  推送中继。
  给模型看的提示词和工具说明不是界面文案，不在这里管。
- `smelt-runtime-client` 里客户端自己说的话（版本不兼容 `Incompatibility`、远程桌面连不上、空 diff）
  用它的 `locales/ui.yml`。
- 智能体要求先登录（ACP `auth_required`，连接时或恢复时）记成结束原因
  `ConversationEndReason::SignInRequired`，按 `SignInAgent` 教人怎么登录，原话当细节。
- Pi 登录（`agent/` 的 MCP 登录、代答登录预设）的进度和报错带 `note`（`PiLoginNote`，在
  `smelt-model/src/pi_auth.rs`），客户端用 `login_text` 说；`message` 是英文兜底。`agent/` 里其余给人看的
  话写英文。
- 手机端 Rust 层（`smelt-mobile`）自己说的话（连不上、订阅断了、终端头不对、本机库出错）用它的
  `locales/ui.yml`；运行时的控制报错走 `ControlError::text()`。Flutter 按 `SmeltErrorKind` 用自己的
  l10n 说标题，`message` 当细节或 `other` 时的整句。Dart 调错参数这类只给开发者看的话写英文，不进文案表。
- `smelt-model` 里只在客户端算的话（任务说明、互发消息、diff 省略行、MCP 预设、设置和自定义 Agent
  的校验）用它自己的 `locales/ui.yml`，按当前语言说；运行时调到时说英文。

## JS 插件

- 插件经 `"smelt/sdk"` 读响应式 `state().locale`，`t("键", { 参数 })` 和 `computed()` 随宿主状态变化自动重算，不用手动订阅语言变化事件。
- 插件自己的文案放在插件目录下的 `locales/ui.yml`，格式与 Rust crate 相同。`t("键", { 参数 })` 按当前语言取，缺则回落英文，再缺返回键本身；`%{name}` 按参数替换。
- 登记视图、命令、页等需要宿主显示的标题时，用 `"smelt/sdk"` 的 `text("键")`（只接键名）构造随语言切换的文本对象，经 `registerViews` / `registerCommands` 交给宿主。
- 清单文件是 `smelt-plugin.json`，视图的本地化标题由代码里 `registerViews([{ ..., title: text("...") }])` 提供。

## 检查

`cargo test -p smelt-plugin-api --test catalogs` 检查 `crates/` 下所有 Rust crate：每条文案两种语言都有、代码取的键都在、没有没人取的键、用了 `t!` 的 crate 带着文案。JS 插件（`plugins/`）的 `locales/ui.yml` 由 `smelt plugin check <目录>`（`crates/smelt-nsh/src/manifest.rs`）检查。
