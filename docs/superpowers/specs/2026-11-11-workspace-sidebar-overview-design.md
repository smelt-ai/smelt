# 工作区标签与项目悬浮总览

> 此方案的扁平列表、仓库选择和「工作区」命名已被
> [任务工作树与会话分组](2026-11-12-task-worktrees-design.md)替代。
> 无身份色、项目数量入口、悬浮总览与不隐式启动进程的约束继续保留。

## 目标与边界

保留现有「项目 → 会话」层级，通过会话文字标签表达绑定关系，通过项目行的数量标签查看工作区总览。不引入工作区身份色，不改成「项目 → 工作区 → 会话」树。

本设计替代此前的色条建议和当前集中排列工作集行的侧栏实现。界面对用户统一使用「工作区」；内部 `workset` 模型、标识和 RPC 命名不变。

本轮只调整桌面侧栏及直接相关的操作入口，不改变 Git worktree 创建规则、会话绑定存储或仓库接入方式，不增加简介字段或数据库迁移。已有终端、对话和 worktree 不会被自动删除或重建。

## 已确认的核心交互

- 会话右侧保留已有工作区名称标签，在名称前增加分支图标。
- 不使用色条或按工作区分配颜色；文字、图标、背景、边框沿用主题语义样式。
- 项目行右侧显示 `工作区·2`，数字为该项目的工作区数量。
- 悬浮数量标签，展示工作区名字、自动概览和绑定分支名。
- 概览采用仓库数量和名称，例如 `2 个仓库：smelt、tools`，不要求用户填写任务说明。
- 移除目前先列出全部工作区、再列出全部会话的独立工作区行。
- 查看工作区信息、新建工作区均不隐式启动终端。

## 侧栏布局

```text
项目名称                         [工作区·2]  [+]
  对话 A                    [分支图标 test-worktree]
  对话 B                    [分支图标 another-task]
  终端 C                    [分支图标 test-worktree]
```

项目标题、数量标签和现有操作区共享原项目行，不增加第二个「＋」。数量标签常驻可见，不要求先悬浮项目行才能发现。侧栏变窄时优先截断项目名称，标签和操作区不得互相遮挡。

会话继续使用现有排序、置顶、拖拽及键盘导航。属于同一工作区的会话不强制相邻，也不在另一份工作区列表里重复显示。无项目标题的分组模式不另造项目行；会话的工作区标签仍然保留。

会话标签内的图标和名称保持为一个整体，名称可截断，悬浮显示完整名称及绑定分支。选中态仍由会话行本身表示，工作区标签不复用 Agent 运行状态色。

数量按运行时和项目根目录共同确定，与工作区包含的仓库数、绑定会话数无关。两个工作区各包含三个仓库，仍显示 `工作区·2`。关闭最后一个绑定会话不减少数量；未绑定的旧会话不被伪造成一个新工作区。

## 覆层内容

```text
工作区 · 2
────────────────────────────────────
test-worktree                    [⋯]
2 个仓库：smelt、tools
[分支图标] feat/test-worktree

another-task                     [⋯]
1 个仓库：smelt
[分支图标] feat/another-task
```

工作区按现有持久化顺序展示，仓库按其配置顺序展示。概览过长时截断，允许查看完整仓库名单；不通过读取磁盘或执行 Git 临时生成介绍。

分支行显示模型记录的绑定分支名。现有净／脏、ahead／behind 信息作为次要状态保留在条目中，使用已缓存的 Git 状态；数据缺失或查询失败时明确显示状态未知，不把它当作干净或零差异。

当前激活会话若绑定该条目，可用「当前会话」文字标记。判定直接使用激活会话的运行时及 `workset_id`，不能只比较找到的第一个绑定会话。

## 覆层行为

- 悬浮数量标签打开覆层，鼠标移入覆层后保持打开，允许滚动和操作条目。
- 移出触发区和覆层后关闭；打开子菜单或将焦点留在覆层内时不因鼠标离开立即关闭。
- 点击数量标签也可打开；键盘可聚焦并打开，Escape 关闭最上层菜单或覆层，关闭后恢复合理焦点。
- 使用项目行右侧标签作为锚点，避让窗口边界，限制最大高度并允许纵向滚动，不受侧栏宽度裁切。
- 触发标签、覆层和菜单的事件不冒泡成项目折叠、新建会话或会话切换。
- 点击工作区名字或空白处只查看信息，不创建会话，不切换现有会话的 cwd，也不隐式激活某个会话。

这是可以移入和操作的覆层，不是鼠标一离开触发元素就消失的静态 tooltip。复用现有弹层、菜单及主题机制；不为展示工作区增加新的一级导航或持久化选中状态。

## 移除独立行后的操作入口

移除旧工作区行不能同时丢失它携带的显式新建会话、重命名和收工入口。每个覆层条目右侧的「⋯」提供：

- **新建会话…**：在目标工作区内明确选择仓库及现有启动动作，再创建会话。单仓库工作区直接显示该仓库；多仓库工作区先选择仓库，不静默使用排序第一的仓库。复用现有会话启动动作，保留 Agent 对话和终端的区别，只有选择对应动作才启动进程。选择器中显示目标工作区和仓库，最终 cwd 使用该仓库在此工作区的 worktree 路径，绑定的 `workset_id` 不变。
- **重命名工作区…**：沿用现有重命名命令、校验和错误反馈。
- **收工并删除工作树…**：沿用现有确认流程，以及绑定会话、脏状态和未合并分支保护；不得把移除会话、强制删除分支合并成默认动作。

项目原有「＋」保留原来的普通会话入口、项目仓库管理及新建工作区入口。普通项目会话不因浏览覆层而被重新绑定；从工作区条目新建的会话才明确绑定该工作区。

以上操作区是对现有能力的搬迁，不增加点击名字即可启动终端的快捷路径。

## 创建、空状态与异常

- 创建成功：沿用现有创建表单；目录推送更新数量和覆层列表，不自动创建会话、不强制切走当前会话。
- 零工作区：显示 `工作区·0`，覆层说明「暂无工作区，可通过项目右侧＋新建」。不创建占位工作区或终端。
- 工作区无会话：仍然计数并显示，可从条目菜单显式新建会话。
- 重命名、创建或收工失败：复用现有可见错误反馈，不乐观伪造成功，不将失败当作列表为空。
- 运行时离线：保留最后已知列表并标明离线；依赖运行时的操作明确不可用，不悄悄落到本地执行。
- 覆层打开期间目录更新：按稳定工作区 ID 更新内容；目标工作区或项目被删除时关闭失效操作区，不能对另一条目重用旧操作。

## 数据与实现边界

权威数据继续来自 `WorkspaceDirectory` 中的工作区及仓库列表，不添加客户端的平行工作区目录。数量、名字、分支和自动概览从内存投影得到，Git 状态继续使用现有缓存。

渲染及悬浮展示不读 SQLite、不扫描目录、不执行 Git、不发起周期查询。写操作只通过现有显式命令进入后台，完成后依靠目录推送更新。覆层的打开、关闭和焦点状态属于临时 UI 状态，不新增持久化字段。

主要影响 `session_list.rs` 的项目行、会话标签及旧工作区行，以及 `session_list/new_session.rs` 中绑定工作区的显式启动入口。按需要将覆层内容和纯投影逻辑拆到现有侧栏模块下，避免继续堆大主渲染函数。不修改无关的侧栏排序或后端生命周期逻辑。

## 验收要点

1. 深浅主题下名称、分支图标和数量标签均可读，没有硬编码工作区身份色。
2. 项目内有多个工作区时，不再在会话上方集中出现独立工作区行；会话原排序和置顶不变。
3. 一个工作区包含多个仓库或多个会话时，只计为一个工作区；无会话工作区仍然存在。
4. 悬浮可读完整概览，移入可操作，长列表可滚动，点击和键盘可打开；不会触发项目折叠或启动进程。
5. 仅创建、浏览、点击工作区名字均不产生终端；新建会话明确选择启动类型，多仓库明确选择仓库，保存的绑定及 cwd 正确。
6. 同一工作区激活任意一个绑定会话，覆层均能正确标识「当前会话」。
7. 零工作区、名称过长、运行时离线、目录实时更新及操作失败均有明确且不误导的反馈。
8. 新建、重命名和收工仍遵守已有保护；现有数据不被自动清理，原测试中产生的终端由用户显式管理。

实现时优先在已有测试位置增加数量归属、自动概览、激活绑定及显式启动目标的针对性用例。遵循 `AGENTS.md`，未经用户再次授权不运行构建、测试或打包。
