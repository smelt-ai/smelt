# 任务工作树与会话

## 已确认的产品语义

- 项目行保留普通会话入口和独立的「新建工作树」入口。普通任务无需 Git 隔离，直接挂在项目下。
- 工作树是任务目录，包含所选仓库各自的 Git worktree。界面统一称「工作树」，计数是任务目录数，不是仓库数；内部 workset ID、RPC 和存储名称不变。
- 新建绑定会话统一以 `<项目>/worktrees/<任务>` 为 cwd；单仓库和多仓库一致，不再选择仓库。
- 侧栏为「项目 → 工作树 → 会话」。工作树行使用独立折叠箭头和已有分支 SVG；会话保留各自的 Agent／终端图标。
- 同一工作树的多个会话共享文件和分支，但不共享聊天上下文；创建或浏览工作树不隐式启动会话。

## 展示与交互

项目下先保留普通会话原顺序，再按工作树持久顺序分组；每组内部保留已有会话排序和置顶优先级。只在项目分组模式增加这层结构；其他侧栏分组模式仍平铺，并保留工作树标签。

无会话的工作树保留在项目总览中，不单独铺空行。有会话的工作树始终有分组行；行内「＋」打开绑定该工作树的现有会话启动选择器。折叠只影响展示，激活隐藏会话时自动展开父项目和工作树。键盘父子导航与绘制顺序共用投影；拖拽只调整同一工作树（或同为普通会话）的顺序，不改绑定。

点击工作树行选择任务目录上下文并开合，不切换或创建会话。会话切换将文件树和 Git 面板上下文定位到任务根目录；Git 写操作仍以仓库为单位，复用多仓库发现、分组和仓库选择功能。

## 数据与边界

复用现有目录布局，从 project_root 和 task 按运行时 PathStyle 推导任务根目录，不新增数据库字段或迁移。允许根目录及其子目录作为绑定会话的 cwd，拒绝相邻任务、`..` 越界以及项目其他路径；这是绑定一致性校验，不是操作系统沙箱。

既存会话保留绑定和 cwd，不自动 cd、重启或重建。新建会话使用新规则；旧会话激活时工具面板使用绑定任务根，进程 cwd 仍维持原值。

运行时、工作树删除或配置变化在确认启动时重新校验，并显示错误，不静默切换目标。所有菜单沿用现有离线、重命名和收工保护。折叠状态保存在运行时视图内存中，启动默认展开，不增加持久化格式。

## 验证边界

新增任务根路径、路径范围、混合普通／共享工作树投影和键盘父子关系回归；保留此前通知环回归。render 只读内存，不新增 I/O 或父子通知环。

最初「开始实施」未包含重新构建、测试或打包授权；遵循 AGENTS.md，先写用例和做静态格式检查。2026-11-12 用户随后授权针对性编译与测试、修复问题后分步骤创建本地提交，自动化验证结果记于实施计划。用户要求打包时再构建、核验 GUI 活性并重启隔离实例。
